# [Day23 실습 07] 검색 결과 정성평가 및 pgvector 성능 분석 보고서

## 1. 개요 및 실행 환경
* **실습 주제:** Day23 실습 07 · 검색 결과 정성평가 (심화)
* **실행 모드:** `pgvector_exact` (실제 PostgreSQL 및 E5 임베딩 모델 연동 환경)
* **수행 레벨:** Level 3 (전체 검색, 필터 효과 검토, 데이터 무결성 검증 포함)
* **주요 검증 항목:** 
  * 질의별 상위 Top-3 문서 검색 정확도 및 코사인 거리 분석
  * 사람 수동 기준표 (`teaching_reference`)를 활용한 정성평가 대조
  * 메타데이터 필터 적용에 따른 후보군 변화 분석 (`filter_effect`)
  * 예외 상황 처리 정합성 (`empty_is_not_error`) 및 데이터 무결성 검증 (`evaluation_integrity`)

## 2. 질의별 검색 결과 및 정성평가 분석 (`review_rows`)

총 3개의 평가 케이스 (`server`, `retention`, `error`)에 대해 각각 상위 3개 ($k=3$) 문서를 검색하고 수동 기준표와 비교한 결과는 다음과 같습니다.

| 케이스 ID (`case_id`) | 사용자 질문 (`query`) | 검색된 ID (`retrieved_id`) | 코사인 거리 (`distance`) | 교재 기준 라벨 (`teaching_reference`) | 소스 버전 |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **server** | 서버는 어디에서 실행하나요? | **102** | 0.114599 | **관련** (정답) | `knowledge_v1` |
| | | 103 | 0.195967 | 무관 | `knowledge_v1` |
| | | 107 | 0.197790 | 무관 | `knowledge_search_v2` |
| **retention** | 실습 파일은 몇 년 동안 보관하나요? | **101** | 0.099375 | **부분 관련** (정답 근거) | `knowledge_v1` |
| | | 103 | 0.202864 | 무관 | `knowledge_v1` |
| | | 104 | 0.204483 | 무관 | `knowledge_search_v2` |
| **error** | 오류를 질문할 때 무엇을 적어야 하나요? | **103** | 0.127729 | **관련** (정답) | `knowledge_v1` |
| | | **108** | 0.136703 | **관련** (정답) | `knowledge_search_v2` |
| | | 109 | 0.167840 | 무관 | `knowledge_search_v2` |

### 💡 주요 시사점 및 정성적 평가
1. **핵심 정답 포착 능력 우수:** 
   * `server` 케이스의 정답 문서 (ID `102`, 거리 `0.114`)와 `error` 케이스의 핵심 정답 문서들 (ID `103`, `108`, 거리 `0.127 ~ 0.136`)이 모두 가장 낮은 코사인 거리 (높은 유사도)를 기록하며 상위권에 정확히 포착되었습니다.
2. **의미적 유사도와 업무 기준의 괴리:**
   * `retention` 질문 (보관 기간 문의)의 경우, 직접적인 기간 언급이 없는 개인 폴더 보관 문서 (ID `101`)가 가장 가까운 거리 (`0.099`)로 검색되어 '부분 관련'으로 판정되었습니다. 이는 순수 임베딩 모델이 문맥상 키워드를 잘 잡아내더라도, 실제 업무/교육적 기준에서 요구하는 명시적 정답과의 차이가 존재함을 보여줍니다.
3. **소스 버전 통합 검색 안정성:**
   * 기존 `knowledge_v1` 데이터와 확장된 `knowledge_search_v2` 데이터가 원활하게 함께 검색되며, 모델이 다양한 버전의 지식 소스에서 유의미한 후보군을 안정적으로 도출하고 있음을 확인했습니다.

## 3. 검색 상태 및 메타데이터 필터 효과 분석

### ① 검색 상태 분류 (`search_states` & `empty_is_not_error`)
* 모든 케이스 (`server`, `retention`, `error`)에서 정상적인 후보군이 수집되어 `candidates` 상태로 판정되었습니다.
* 또한 빈 결과 반환 (`[]`) 시의 상태 (`empty`)와 데이터베이스 연결 장애 시의 상태 (`error`)가 명확하게 분리되어 처리됨 (`empty_is_not_error: true`)을 검증하여, 예외 처리 로직의 견고함을 확인했습니다.

### ② 메타데이터 필터 영향 분석 (`filter_effect`)
* **필터 적용 전후 ID 비교:**
  * 제거된 항목 (`removed`): `[103]`
  * 추가된 항목 (`added`): `[106]`
* **해석:** 카테고리 필터 (`development`)를 적용함에 따라 일반 공통 안내 성격의 문서 (ID `103`)는 후보군에서 제외되고, 개발 카테고리에 특화된 문서 (ID `106`)가 새롭게 유입되었습니다. 이는 순수 벡터 검색 결과에 메타데이터 필터링이 결합될 때 검색 결과의 전문성을 높이면서도 후보군 구성에 변화를 준다는 점을 명확히 증명합니다.

## 4. 데이터 무결성 및 시스템 신뢰성 검증 (`evaluation_integrity`)
* **검증 결과:** `evaluation_integrity: true`
* **해석:** 
  * 동일 케이스 내에서 `retrieved_id`의 중복 발생 여부 검사 통과
  * 지식 ID 범위 (`101~109`) 외의 비정상 ID 유입 여부 검사 통과
  * 원문 소스 버전 (`source_version`)의 일치 여부 검사 통과
* 위 결과들을 통해 평가 데이터셋 전체에 결손이나 버전 불일치 문제가 전혀 없으며, 완벽한 무결성 상태에서 정성평가가 수행되었음을 보증합니다.

## 5. 결론
본 실습을 통해 실제 `pgvector` 기반의 Exact Search 환경에서 E5 임베딩 모델이 의미론적으로 정확한 상위 문서를 안정적으로 검색해 냄을 확인했습니다. 아울러 수동 기준표와의 대조를 통해 모델 검색 점수와 실제 사용자/교육적 기준 사이의 차이를 인식하고, 메타데이터 필터 및 무결성 검증 로직이 현업 수준의 RAG 파이프라인에서 어떻게 동작하는지 성공적으로 검증할 수 있었습니다.
