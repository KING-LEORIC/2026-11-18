* **소스 버전 공존:** 구버전(`knowledge_v1`)과 신버전 소스(`knowledge_search_v2`)가 혼재된 환경에서도 벡터 공간 상에서 유의미한 상위 후보군이 안정적으로 필터링되었습니다.

## 4. 구조적 한계 및 비판적 분석 (Critical Analysis)

본 실습 환경은 아키텍처의 뼈대와 계약 무결성을 검증하는 데는 훌륭하나, **프로덕션 레벨의 성능 평가 관점에서는 다음과 같은 명확한 구조적 한계**를 지닙니다.

1. **소규모(9건) 토이 데이터셋의 한계 (변별력 부족):**
   * 데이터가 9건에 불과하여 벡터 공간이 지나치게 헐겁습니다. 복잡한 오답 후보(Distractor)나 의미적으로 교묘하게 헷갈리는 문들이 존재하지 않기 때문에, 현재의 높은 정확도가 대규모 데이터에서도 유지된다고 보장할 수 없습니다.
2. **인덱스 최적화 검증 불가능:**
   * 데이터 규모가 작아 HNSW나 IVF 같은 ANN(Approximate Nearest Neighbor) 인덱스의 성능 개선 효과와 검색 재현율(Recall) 저하 트레이드오프를 체감하거나 평가할 수 없습니다.
3. **밀집 벡터(Dense Retrieval) 단일 의존의 취약성:**
   * E5 모델 기반의 의미 검색에만 의존하고 있어, 특수 고유명사, 코드 스니펫, 정확한 키워드 매칭이 필요한 질의에서 오작동할 위험이 존재합니다.

## 5. 실무(Production) 확장을 위한 개선 로드맵

완벽한 RAG 및 AI Agent 시스템 구축을 위해 향후 반드시 보완해야 할 핵심 과제는 다음과 같습니다.

* **대규모 코퍼스 및 벤치마크 셋 구축:**
  * 최소 수천~수십만 개의 청크 문서와 도메인별 질문-정답 쌍(Golden Testset)을 확보하여 성능 지표(Precision@K, MRR 등)를 정량 측정해야 합니다.
* **하이브리드 검색 (Hybrid Search) 도입:**
  * 키워드 기반의 BM25(Sparse Retrieval)와 E5 Dense Retrieval을 결합하여 어휘적 정확성과 의미적 유연성을 모두 확보합니다.
* **정량적 RAG 평가 프레임워크 적용:**
  * `RAGAS` 또는 `TruLens` 등을 도입하여 컨텍스트 관련성(Context Relevance), 충실도(Faithfulness), 답변 정답률을 지속적으로 모니터링합니다.
